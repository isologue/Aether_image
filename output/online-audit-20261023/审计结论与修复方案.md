## 修复建议与顺序
### P0：停止无意义切号，修复图片输入兼容
1. 将参数校验、输入资源错误、账号认证、额度、上游瞬时异常拆成独立错误类型。请求级确定性错误不切号、不惩罚账号；明确返回 400/413 等恰当状态，不再统一变成 503。
2. 在选账号前完成通用参数及图片校验。按安全的文件签名识别 PNG/JPEG/WebP，规范化通用 octet-stream；声明 MIME 不符时纠正安全栅格格式或明确报格式不匹配。保留大小、内容及 SSRF 保护，禁止任意文件/SVG 借此通过。
3. Data URL 与 HTTP URL 显式分支；非法 Data URL 不得回退成 HTTP URL 报错。参考图确定性 404 直接报告输入资源不可用，不随切号重复下载。
4. 提示词阈值明确按 UTF-8 字节反馈；如需提高阈值，先验证实际运行链路和上游能力，不静默截断。
### P1：完善能力、拒绝和终态
5. n=2 要么前置明确提示单次最多 1 张，要么实现网关拆分与结果聚合，并定义部分失败和计费；不能只修改上限常量就声称完整支持。
6. 明确拒绝优先识别为 content_refused，正常返回拒绝文字、不重试、不扣费；补充 EOF、DONE、消息终态以及 patch/snapshot 重建的回归测试，避免一字摘要及终态矛盾。
7. 对 /v1/responses 按协议、模型和提供商能力给出准确诊断；需要兼容时做显式适配，不靠新增别名假装支持。
8. 对 5 条大 JSON 编辑请求用脱敏、最小输入复现，记录解析、模型解析、能力匹配和执行规划的具体退出原因，保留真实模型名。
### P2：可观测性与调度
9. 103 条失败的 usage.error_message 均为空，应持久化安全根因、首次错误、最终错误、总耗时、最后尝试耗时及重试次数。
10. 额度失败及时更新调度状态，在真正发送前再次校验，减少已排队任务浪费。现有证据不足以直接认定额度缓存或并发上限有 bug。

## 验证标准
使用合成图片和测试账号进行回归：octet-stream、MIME 不符、超长中文提示词、n=2、输入 404、明确拒绝、EOF/DONE 消息终态及大 JSON。确定性输入错误只处理一次；拒绝不切号、不扣费；有效图片格式转换成功；上游 401/额度/5xx 保持各自合理状态处理。
