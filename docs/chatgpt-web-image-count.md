# ChatGPT Web 单次图片数量配置

系统设置 → 图片生成 → **ChatGPT Web 单次请求图片数量上限（n）**。

- 配置键：`chatgpt_web_image_max_count`，默认 `1`，支持 `1–10` 的整数。
- 保存后对新请求生效，无需重启。客户端未传 `n` 时仍按 `1` 处理。
- 该值是允许的上限，不会把所有请求强制改为此数量。例如上限为 `3`，`n=2`、`n=3` 可以进入 ChatGPT Web；`n=4` 返回配置限制错误。
- 适用于图片生成及图片编辑请求，包括 JSON 和 multipart；同步和异步任务使用同一执行路径。
- 多图是实验能力：请求数量会以 `n` 字段加入 ChatGPT Web 会话请求。原来的单图会话请求保持原样，不修改用户提示词，也不拆成多个上游任务。上游是否识别该参数需实际测试。
- 收到多张图片时，最多返回请求的数量；上游返回少于 `n` 张时返回已取得的实际结果，不为凑数追加任务。同步结果的 `data` 包含多张图；流式结果逐张发送 completed 事件，多图事件增加从 `0` 开始的 `image_index`，整次用量仅在最后一个事件返回。
- 多图输出 token 估算按实际取得的图片累加，输入 token 只计一次。原来的图片存储、缩放及整体响应大小限制继续适用。
- 其他提供商继续使用原有能力限制。

## 测试示例

将上限改为 `3` 后，向原图片接口发送：

```json
{
  "model": "gpt-image-2",
  "prompt": "生成测试图片",
  "n": 3
}
```

通过响应中的实际图片数和 `chatgpt_web_image_output_count` 日志里的 `requested_count`、`returned_count` 判断结果。放开本地限制不等于已确认上游支持多图。

## ChatGPT Web 提示词本地长度限制

系统设置 → 图片生成 → **ChatGPT Web 提示词本地长度限制（字符）**。

- 配置键：`chatgpt_web_image_max_prompt_chars`，默认 `32768`，支持 `0–1000000` 的整数。
- 单位是 Unicode 字符，不是 UTF-8 字节；中文、英文和 emoji 都按字符计数。请求转换层和实际执行层使用同一配置。
- 设置为 `0` 时跳过 Aether 的提示词长度检查，超长提示词仍会发送给 ChatGPT Web，由上游返回实际支持范围和错误。它不代表 HTTP 请求体、图片输入、内存等其他安全限制也被取消。
- 正整数只代表 Aether 的本地保护上限；达到上游真实限制时，上游仍可能返回 400。配置保存后对新请求热生效，无需重启。

例如，要测试上游能力，可将该项改为 `0`，再逐步增加提示词长度；错误信息中的 UTF-8 bytes 是上游或网关诊断信息，不应与此配置的字符数直接混淆。
