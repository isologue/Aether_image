# 账号池 AT / RT 刷新状态

号池管理的“刷新 AT：可／否”表示账号是否具备后台 OAuth 自动刷新资格，页面和后台任务共用同一套判断。“可”不保证 RT 一定有效：尚未实际刷新过的 RT 会明确显示“尚未验证”。

自动任务由“系统设置 → 定时任务 → OAuth Token 自动刷新”控制，默认开启，每 60 秒扫描一次，提前 120 秒刷新即将到期的 AT。账号首次被标记为 AT 认证失败（`[OAUTH_EXPIRED]`）后，即使记录的到期时间尚未到达，也会在下一轮尝试 RT 恢复。

刷新失败按原因处理：

- `refresh_token_invalidated`、`refresh_token_reused`、`refresh_token_expired`、`invalid_refresh_token` 等明确失效错误：显示“否”，停止自动重试，需要重新登录或更换 RT。
- 其他非临时拒绝（例如未提供明确错误码的 401）：显示“否”，说明“刷新失败，未确认 RT 失效”，可检查授权配置后手动重试。
- 网络故障、无效响应、408、429、5xx：保留“可”，退避 5 分钟再尝试，不据此判定 RT 永久失效。
- 缺少 RT、不支持刷新、账号停用或封禁：显示“否”。

Hover 会分别显示 AT 状态、RT 状态、固定原因说明、确定失效的错误码、最近刷新时间及退避时间。状态诊断不包含令牌或上游响应原文，不受日志脱敏开关影响。

手动刷新仍保留用于排查。刷新成功会清除可恢复的 AT 失效标记及 RT 失败记录；替换为新的 RT 后，旧 RT 的结构化失败状态不再阻止自动刷新。旧部署已保存的明确 RT 失效原因也会被识别并停止重试。
